# متابعة التنفيذ

١. يجب سؤال المستخدم عن اختيار المؤسسة قبل إنشاء Supabase. المتاح الوحيد حاليًا مؤسسة `eslam`، ولم يُعتمد الاختيار بعد. بعدها ينفذ إنشاء مشروع مخصص لرونق، دون اختيار مشروع آخر أو استخدام بيانات مصطنعة. أي تكلفة غير صفرية تتطلب موافقة على السعر المعلن.
٢. افحص حالة المشروع، ثم الجداول قبل تطبيق الترحيل. طبّق ملف الترحيل ثم ملف البذور، وراجع الصلاحيات والأمان على Supabase الفعلي.
٣. اجلب URL والمفتاح العام فقط، ومررهما لإعدادات Vercel؛ لا تطبع أسرارًا أو تضع مفاتيح إدارية في الواجهة.
٤. إنشاء أول حساب إدارة وتفعيل حسابات الموظفات يجب أن يستخدم معلومات معتمدة. لا كلمات مرور افتراضية ولا إنشاء حسابات بأسماء مخترعة.
٥. Vercel رفض إنشاء المشروع بسبب تصريح الفريق. استخدم authorize_team_access لنفس team ID عند استئناف النشر، واعرض الرابط الجديد. الرابط السابق انتهى؛ لا تستخدمه.
٦. تأكد الوصول والكتابة إلى المستودع الخاص https://github.com/eslamtiger/rawnaq-after-led يوم ٤ نوفمبر ٢٠٢٦. هذا المستودع مخصص لرونق، ولا تستخدم مستودع معارج.
٧. اختبر تدفقًا حيًا بالكامل بعد الربط، بما فيه RLS بحسابي موظفتين، ثم حدّث ملفات الحالة والقبول. بيانات الاختبار يجب فصلها بوضوح عن التشغيل.
٨. لا تعتبر شاشة «تجهيز الاتصال لم يكتمل» تطبيقًا عاملًا أو تسليمًا نهائيًا. لا توجد نسخة منشورة حاليًا.

الكود جاهز للبناء ويحتوي اختبارات مستقلة. `README.md` يوضح المنهج والحدود. لا يحتوي الأرشيف على node_modules أو بيانات عميلات أو مفاتيح اتصال فعلية.
